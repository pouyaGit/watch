# Stage R28.1 — Bug Bounty Research Intelligence Product API

## Status
**IMPLEMENTED (product API contract v1).** Watch's existing research
intelligence is now exposed as a clean, consumer-oriented, read-only API
that a researcher, browser extension, CLI client, other platform or future
SaaS frontend could consume. No formulas changed, no lifecycle behavior
changed, no writes, no execution, no payouts, no billing, no accounts.

## 1. Product API rationale

Internal stages (R25.2 Money Score → R26.1 opportunities → R26.2 actions)
produce rich projections, but their schemas are internal working models with
subscores, rates, templates and provenance that must never become accidental
public contracts. R28.1 freezes an explicit, minimal public surface —
`ResearchOpportunityResponse` — mapped field-by-field from the internal
models, so internal refactors can never leak into the consumer contract.

The resource represents CVE + asset relevance + research evidence + economic
priority + recommended action. It never represents a confirmed vulnerability,
a bounty prediction, target exploitability or a scan result.

## 2. Public schema (`ai/schemas/product_api.py`, 229 lines)

`ResearchOpportunityResponse` (21 fields, `extra="forbid"`):
`opportunity_id, lead_id, cve_id, program, opportunity_class, money_score,
money_priority, confidence, evidence_quality, estimated_minutes,
current_status, recommended_action, why_now, why_valuable, blockers,
next_step, research_status, outcome_status, session_status, research_only,
api_version`.

`PRODUCT_API_VERSION = "v1"` — independent of `r25-1`/`r26-1`/`r26-2`/`r26-3`,
all asserted unchanged. Future breaking changes require `v2`. Deliberately
dropped internal fields: subscores, rates/counts (acceptance, wasted,
efficiency, sessions), ids beyond opportunity/lead, templates, reason
provenance, task/queue ids.

Error contract: `{"api_version", "error": {"code", "message"},
"research_only"}` with closed codes `INVALID_REQUEST / NOT_FOUND /
UNAUTHORIZED / INTERNAL_READ_ERROR` and pre-sanitized static messages only.

## 3. Endpoint contract (`backend/product_api.py` 199 lines + `backend/routers/product_api.py` 129 lines, registered in `api.py`)

| Route | Behavior |
|---|---|
| `GET /api/v1/opportunities` | ranked list; `limit` 1–100, `offset` ≥ 0, `cve`, `program`, `class`, `action`, `status`, `min_money_score` 0–100 (clamped); R26.2 ordering reused verbatim |
| `GET /api/v1/opportunities/{lead_id}` | one record; malformed/unknown → v1 404 envelope |
| `GET /api/v1/opportunities/summary` | `total`, `by_class`, `by_action`, `by_status`, top 3, version flags |
| `GET /api/v1/research/status` | counts by status, evidence/outcome/session availability booleans; no secrets, no target data |

Auth reuses the existing `verify_api_key` dependency only (no second
mechanism; no accounts/OAuth). Bounds are application-level only (no Redis,
no rate service). The dedicated router keeps product routes isolated from
internal routes; no existing route was moved or renamed.

## 4. Authentication

Single existing API-key boundary (`X-API-Key` header or `?api_key=`).
Tests assert 401 without a key on all four routes. No keys in URLs are
generated by the API (docs show the concept only); nothing is logged.

## 5. Error contract

Verified: malformed CVE → `400 {"error": {"code": "INVALID_REQUEST"}}`;
unknown/malformed lead → `404 NOT_FOUND`; missing key → `401` via existing
boundary. Envelopes always carry `api_version: "v1"` and
`research_only: true`; no stack traces, paths, credentials, env values,
Mongo URIs or provider keys (asserted by scan).

## 6. OpenAPI

`/openapi.json` exposes all four paths; each carries summary + description
stating *"Read-only research intelligence. Does not perform security
testing."* (asserted). `/docs` and `/openapi.json` remain auth-exempt per
existing convention.

## 12. Security audit

- `research_only: true` on every schema instance, response, CLI item and
  error envelope.
- Static token scan on all three new modules: no subprocess/socket/requests/
  httpx/LLM/Nuclei/selenium/playwright imports or calls.
- No writes (GET-only router; composition reads local projections only),
  no findings/alerts, no payout prediction or billing, no new persistence
  (no collections, workers, systemd, `.env` changes).
- Secret hygiene asserted on `/api/v1/research/status` (no provider keys,
  Mongo URIs, model names, target hostnames).
- `git diff --check` clean; formulas and lifecycles byte-untouched.

## 13. Limitations

- Read surface only: no creation, execution, scanning, validation, alerting
  or notifications.
- Coverage reflects only locally researched CVEs (2 opportunities today);
  empty filters return explicit empty lists.
- `min_money_score > 100` clamps to 100 (documented bound behavior).
- OpenAPI descriptions are static strings; the 401 path keeps the existing
  middleware shape (unchanged by this stage).
- No multi-user auth, rate service, SLA or pagination cursors — v1 is a
  contract foundation, not a hosted product yet.

## 14. Exact next-stage recommendation

**R28.2 — Product API consumption proof (read-only client, no new endpoints).**

   never silently extend v1.
